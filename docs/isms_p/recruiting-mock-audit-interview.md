# 관리체계 면접 준비 — 인터뷰·증적·결함 판단

> **전부 교육용 모의 사례다.** 실제 고객사 인터뷰, 내부 감사, 정식 인증심사 또는 경영진 승인으로 표현하지 않는다.

## 1. 신입 컨설턴트가 접근권한 통제를 점검한다면?

**질문**
- 사용자 계정은 누가 신청·승인하는가?
- 부서이동·퇴사 때 계정은 누가 어떻게 회수하는가?
- 관리자 권한은 누구에게 부여되고 정기적으로 검토되는가?
- 예외권한은 언제 만료되고 누가 재검토하는가?

**요청할 자료(예시):** 계정관리 정책, 현행 계정·권한 목록, 신청/승인 기록, 퇴사자 명단과 회수 기록, 정기 검토 결과.

**판단 예시**
- "정기 점검합니다"라는 구두 답변이나 정책 문서만 제출 → 실제 수행 여부 추가 확인.
- 특정 날짜의 계정대장과 서명된 검토 결과, 정정조치 증거 확보 → 해당 범위의 운영 정황 확인.
- 개인정보 포함 자료나 고객사 기밀은 공개 포트폴리오에 업로드하지 않음.

**내 프로젝트와 연결:** Analyst/Security Admin 기능 분리는 확인했지만, 정기 조직 권한 검토는 미구현([GAP Matrix](03_control_gap_matrix.md)).

## 2. 로그 점검 통제를 점검한다면?

**질문**
- 어떤 시스템의 어떤 이벤트를 누가 수집하는가?
- 로그 보존기간과 조회권한은 누구에게 있으며 변조방지 수단은?
- 이상 이벤트의 점검 기준, 수행 주기, 결과 보고/조치는?
- 실제 검토를 수행했다는 증거는 어떤 기록인가?

**요청할 자료(예시):** 로그 정책, 수집 설정, 접근권한, 검토 대장, 이상징후 조치 기록, 시스템 시각 동기화 결과.

**판단 예시**
- 파일에 로그가 있음 → '로그 생성' 확인에 그침.
- Audit Review 코드가 임계치를 표시함 → 프로젝트 기능 구현 확인.
- 정기 검토 서명·조치 실적 없음 → 운영상 '정기 수행 완료'로 판정 불가.

**내 프로젝트와 연결:** 30일 read-only Audit Review 구현; 중앙/WORM 보호와 조직 승인 이력은 미확인.

## 3. 위험평가를 설명하라는 질문

- **위험 시나리오:** "백업을 복원하지 못해 장애 발생 시 서비스 복구 실패".
- **현재 프로젝트:** R-06, 가능성 3 × 영향 5 = 15(HIGH)라는 자체 모형. 이 값은 외부 통계적 확률이 아니라 프로젝트의 상대적 판단.
- **처리 방향:** 백업·복원 검증 수행 계획. 현재 OPEN이므로 '복구 검증 완료'라 할 수 없음.
- **실제 기업이라면 추가 확인:** 자산 중요도, 업무 연속성 목표, 승인된 RTO/RPO, 실제 복구 로그, 담당자 및 승인 이력.

## 4. 개인정보 관련 통제를 설명하라는 질문

- 프로젝트의 retention DRY RUN과 확인 절차는 실제 법정 보유기간 적정성의 판단이 아님.
- 실제 검토 시 개인정보 처리의 법적 근거, 보존의무, 파기 방법, 승인·삭제기록 등을 확인해야 함.
- 실데이터 유출이나 정보주체의 개인정보 처리 실적은 없으므로 법률 준수를 확정하지 않음.

## 5. 관리체계 면접 핵심 질문 12개

1. **ISMS-P 모의진단 범위를 왜 21개로 제한했습니까?** 시스템에서 코드·설정·증적 또는 부재를 확인할 수 있는 항목을 선정했기 때문입니다.
2. **공식 인증을 받은 것입니까?** 아닙니다. 내부 실습용 자체 모의진단입니다.
3. **정보자산 15개의 의미는?** 시스템 내 점검 대상을 관리하기 위해 식별한 프로젝트 자산 수입니다. 고객사 전체 자산 수가 아닙니다.
4. **위험등록부 12개는 무엇을 말합니까?** 시스템 운영의 위험 시나리오이며 다크웹 게시글의 유출 사고 12건이 아닙니다.
5. **위험 5×5의 의미는?** 가능성과 영향도 1~5를 가정해 곱한 상대평가입니다. 실제 사고확률을 추정한 결과가 아닙니다.
6. **왜 구현된 기능도 PARTIAL입니까?** 조직 정책·정기 검토·승인·운영 증적은 별도의 확인 조건이기 때문입니다.
7. **접근권한 분리 개선은 무엇입니까?** Analyst 조회와 Security Admin 감사 검토 권한 분리입니다.
8. **로그 검토 개선은 무엇입니까?** 최근 30일 감사 이벤트를 읽기 전용으로 집계·주의표시하는 기능입니다.
9. **백업 복구는 검증했습니까?** 하지 않았습니다. R-06은 OPEN입니다.
10. **실제 심사원이 요청할 자료는?** 기준과 범위에 따라 정책, 승인, 운영 기록, 시스템 설정을 교차 확인해야 합니다.
11. **기업이 위험을 수용하면 끝입니까?** 승인권자, 기간, 대체 통제, 재검토 조건 및 잔여위험 기록이 필요합니다.
12. **기술진단과 관리체계 점검의 차이는?** 개별 시스템 설정/동작 판단과, 조직이 정책·실행·증거·개선을 지속 운영하는지의 판단을 구분합니다.
