# ISMS-P·관리보안 컨설팅 지원용 사례 브리프

> **범위 고지:** 2025.11~12 다크웹 모니터링 시스템은 3인 **팀 프로젝트**, 이후 시스템을 대상으로 한 ISMS-P **21개 선정 통제항목의 자체 모의진단**은 개인 후속 작업이다. 실제 인증심사·고객사 수행·조직 승인 이력은 없다.

## 30초 설명

"팀 프로젝트로 개발한 다크웹 위협정보 모니터링 시스템을 대상으로, 개인적으로 ISMS-P 관련 통제 21개를 선별했습니다. 자산 15개와 데이터 흐름을 정리하고 GAP Matrix, 위험등록부 12개 시나리오, 개선계획과 증적목록을 연결했습니다. 권한 구분 부족과 감사로그 정기 검토 부족을 확인해 일부 기능을 개선했으나, MFA·백업복원·실제 조직 승인 등은 미검증 또는 미구현으로 남겼습니다."

## 왜 21개를 선정했는가?

코드·구성·자산·데이터 흐름 또는 증거 부재를 실제로 확인 가능한 시스템 연계 통제만 선택했다. 조직 인사·물리보안·경영진 승인·제3자 피해기업의 운영은 점검 범위에서 제외했다. 이는 101개 전체 ISMS-P 인증심사와 다르다.

## 사례 A — 관리자 권한 분리

| 구분 | 증거 기반 설명 |
|---|---|
| 최초 GAP | 로그인 사용자의 governance 기능 접근권한 구분 부족 |
| 관련 통제 | 2.5.1 사용자 계정 관리, 2.5.5 특수 계정 및 권한관리 |
| 개선 | 일반 Analyst와 Security Admin 역할을 구분. Django staff 기반 Security Admin만 감사 검토 기능에 접근 |
| 결과 | 익명 사용자 로그인 유도, Analyst governance 요청 403 등 접근 제어 기능 구현/테스트 기록 |
| 잔여 한계 | MFA·정기적인 실제 조직 계정/권한 검토 절차 미구현; 완전 적합 판정 아님 |

원문: [GAP Matrix](03_control_gap_matrix.md) · [최종 평가](07_final_assessment.md) · [증적 인덱스](06_evidence_index.md).

## 사례 B — 로그는 있는데 검토하지 않는 문제

| 구분 | 증거 기반 설명 |
|---|---|
| 최초 GAP | 감사로그 생성 기능은 존재하지만 정기 검토 기준·도구 부재 |
| 관련 통제 | 2.9.4 로그 및 접속기록 관리, 2.9.5 로그 및 접속기록 점검 |
| 개선 | 최근 30일 current/rotated audit.jsonl을 읽기 전용으로 집계하는 Audit Review 구현 |
| 결과 | 로그인 실패·접근거부·오류·retention 오류 등의 임계값 초과 시 ATTENTION 표시 |
| 잔여 한계 | 조직적 검토 승인, 중앙/WORM 로그 보존, 자동 경보/조치 워크플로 미확인 |

## 기술적 취약점 진단과 어떻게 연결되는가?

- 기술적으로 "일반 사용자가 관리자 검토 화면에 접근 가능"을 확인했다면, 관리체계에서는 **권한 부여 기준·변경 승인·정기 검토·증적**까지 확인해야 한다.
- "로그 파일이 생성됨"을 확인했다면, 관리체계에서는 **누가 어떤 주기로 검토하며 이상 징후를 어떻게 조치하고 증거를 남기는지**를 확인해야 한다.
- 이 프로젝트는 **기술 통제의 구현/검사**를 일부 보여 주며, 조직 운영의 반복성과 승인 이력까지 입증한 것은 아니다.

## 취업용 한 문장

"ISMS-P 관련 21개 선정 통제항목을 대상으로 자산·GAP·위험·개선계획·증적을 연결하고, 권한 분리와 감사로그 검토의 일부 기술 통제를 개선했습니다. 조직적 운영·실제 인증 대응은 모의진단 범위 밖으로 명확히 남겼습니다."
